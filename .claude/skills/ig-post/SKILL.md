# 文章 → IG 輪播貼文

輸入一篇部落格文章，輸出一個資料夾 `ig/<slug>/`：

```
ig/<slug>/
  slides.html     # 全部投影片，用 ?s=N 指定第幾張
  out/01.png ...  # 自動截圖（1080x1350）
  caption.md      # 標題、內文、標籤
```

`ig/` 整個被 `.gitignore` 忽略，**不要 commit、不要 `git add -f`**。工具（`render.js`、`template.html`）放在這個技能資料夾，會被追蹤。

## 輸入與網址

* 輸入可以是 `source/_posts/` 下的檔案，或 `https://blog.deanyang.cc/YYYY/MM/DD/<slug>/` 這種網址。
* 網址對應檔案：`<slug>` 就是檔名去掉日期前綴與 `.md`，例如 `https://blog.deanyang.cc/2026/10/20/leetcode-3679-minimum-discards-balance-inventory/` ↔ `source/_posts/2026-10-20-leetcode-3679-minimum-discards-balance-inventory.md`。**優先讀本機檔案**，找不到才用網址。
* 部落格網址前綴固定是 `https://blog.deanyang.cc`，文案裡放的文章連結都用這個前綴，格式 `https://blog.deanyang.cc/YYYY/MM/DD/<slug>/`（日期取自 front matter 的 `date`）。不要寫成 `github.io`。
* 資料夾名稱 `<slug>` 用檔名去掉日期的部分，如 `leetcode-3679-minimum-discards-balance-inventory`。

## 步驟

1. **讀文章**，挑出這幾樣（缺的不要編）：題目一句話白話、範例、暴力解與為什麼慢、關鍵觀察（整題的一句話）、問題如何轉換、演算法三步、核心程式碼（取最短、最能說明的一份）、易錯點、複雜度、題解作者與原題解連結。
2. **規劃 10 張**（8 到 10 張，不超過 10）。有兩種解法時，張數可以到 10 但每種解法各用 1 到 2 張，不要複製整篇。

   | 張 | 內容 |
   |---|---|
   | 1 | 封面：題號、題名、一句鉤子（用問句或反差），不劇透答案；底部「往右滑 →」與署名 |
   | 2 | 題目白話：生活比喻或一句話題意，加一個小範例 |
   | 3 | 暴力解：怎麼做、為什麼慢（寫出複雜度） |
   | 4 | 關鍵觀察：整題的一句話洞察，這張最重要 |
   | 5 | 問題轉換：把原題變成更簡單的等價問題 |
   | 6 | 演算法機制：滑動、指標移動等，用小方塊或箭頭畫出一兩步 |
   | 7 | 逐步圖解：同一個範例走完整個過程（表格或分鏡） |
   | 8 | 核心程式碼：最多約 12 行，關鍵行高亮 |
   | 9 | 小技巧／易錯點：最多 3 條 |
   | 10 | 總結：通用模板或口訣；收藏、追蹤號召；下一題預告；署名題解作者 |

   **張數表是預設，依文章調整，不要硬套：**
   * 文章沒有暴力解（或暴力解不是重點）時，第 3 張改成**題意圖解**：把題目用圖畫出來（例如 3439 的會議時間軸、3694 的方格路徑），再接第 4 張的關鍵觀察。
   * 題目本身要先花一張才看得懂（要先建立資料結構、先轉換表示法）時，把第 2、3 張合併成一張，騰出一張給「先看圖」。
   * 沒有易錯點時，第 9 張改成「複雜度與為什麼是 O(n)」或「變形題／同類題」。
   * 沒有下一題可預告時，第 10 張省略該行，不要編造題號。
   * 一律保留第 4 張（關鍵觀察）和第 7 張（逐步圖解），這兩張是整篇的價值所在。
3. **做 `ig/<slug>/slides.html`**：複製 `template.html`（這是 LeetCode 3694 的成品，當作樣板），保留 `<style>` 與最後的 `<script>`，**重寫每個 `<section class="slide" data-n="N">`** 的內容，並更新每張的進度條 `width` 與 `N / 總數`。可用的元件見下方「版面元件」。
4. **截圖**：在專案根目錄執行

   ```bash
   node .claude/skills/ig-post/render.js <slug>
   ```

   需要本機有 Chrome 或 Edge，不需要裝額外套件。
5. **逐張看圖檢查**（用 Read 打開 `out/NN.png`），修到沒問題再收工。常見要修的：
   * 內容壓到底部進度條（`.foot`，約 y > 1200）：縮小字級、減少 padding、或刪字。
   * 標題斷成兩行且最後一行只剩一兩個字：縮短標題，或對該 `<h2>` 加 `style="font-size:64px"`。
   * 表格或程式碼超出卡片：減少行數、拆成兩張。
   * 中文字沒有被字型吃掉（變成方框）：換 `font-family` 的順序。
6. **寫 `ig/<slug>/caption.md`**（格式見下方）。
7. 回覆使用者時，列出產出的資料夾路徑、張數、有檢查過哪些張、哪些地方沒驗證。

## 版面規則

* 尺寸 1080x1350（4:5）。正文字級至少 36px，標題 64 到 112px；一張最多 3 到 4 個重點。
* 配色沿用部落格 Fluid 主題：深藍灰 `#2f4154`（封面、結尾底色）、連結藍 `#0366d6`、hover 青 `#30a9de`、正文 `#3c4858`、成功綠 `#1a7f37`、錯誤紅 `#cf222e`。其他顏色都已定義成 CSS 變數，不要另外寫死色碼。
* 同一篇的所有張共用同一個範例，不要中途換例子。
* 每張底部固定有進度條與頁碼，封面和結尾用深色底，其他用淺灰底。

### 版面元件（template.html 已定義）

| 元件 | 用法 |
|---|---|
| `.top` | 頂部：左邊 `.kick` 小標、右邊補充說明 |
| `h1` / `h2` | 封面大標、一般標題 |
| `.card` | 白色卡片；`.dark` 底時要自己覆蓋背景色 |
| `.chips` + `.chip` | 字元方塊；`.win` 視窗內、`.rm` 被移除（紅框刪除線）、`.dim` 淡化、`.sm` 小號 |
| `table` + `tr.dup` | 表格；`tr.dup` 標紅底表示重複 |
| `.eq` | 等寬大字算式，`.r` 強調色 |
| `.code` + `.k`/`.c`/`.h` | 深色程式碼區；關鍵字、註解、高亮行 |
| `.tag` / `.tag.g` / `.tag.r` | 小標籤（藍／綠／紅），例如「入」「出」「重複」 |
| `.pill` | 膠囊按鈕，例如「往右滑 →」 |
| `.foot` + `.bar` | 底部進度條 |

## 文案 `caption.md`

固定三段：

```markdown
## 標題（封面第一行，也是貼文第一行）
一句話，含鉤子與「N 張圖看懂」，可加一個 emoji

## 內文
LeetCode <題號>｜<中文題名>
<兩三句題意>

💡 <關鍵一句話>
<兩三句說明轉換與演算法，最後帶複雜度>

👉 往右滑 N 張：<張數的條列，封面不算>

📌 收藏起來，<使用情境>
➕ 追蹤我，下一題：<若無下一題就省略這行>

🙏 題解思路與程式碼整理自 LeetCode 題解作者「<作者>」
原題解：<原題解連結>
完整互動圖解：https://blog.deanyang.cc/YYYY/MM/DD/<slug>/

（IG 貼文內的連結不能點，連結請同時放在個人檔案的連結欄。）

#leetcode #演算法 #<演算法 tag> ...（8 到 10 個，精準，不要塞滿）
```

規則：

* 作者名保留原樣，`灵茶山艾府` 用簡體原名，不轉繁體。
* 原題解連結取自文章的標注引用；文章裡沒有就省略這行，並在回覆中說明，**不要編造連結**。
* 連結只是從文章複製，沒有實際打開驗證，回覆時要這樣說。
* 內文第一屏（約前兩三行）要能獨立成立，因為 IG 只會先顯示這一段。

## 注意

* 不要把使用者沒給的資訊寫進圖裡（難度、通過率、競賽場次若文章沒寫就不要放）。
* 沒有實際在手機上看過 IG 的顯示效果，回覆時要說明只檢查了截圖。
* 只做出圖與文案，**不要發佈**，也不要上傳到任何地方。
